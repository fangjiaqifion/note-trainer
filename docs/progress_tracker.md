## NT-001：账户身份与训练／测试数据长期保存

用户诉求：更新游戏时保留已有数据；老师和学生使用独立账号、密码和显示姓名，
避免把中文姓名当作身份匹配依据。跨设备同步是否实施、后端选择及具体注册流程尚未决定。

已核查的现状（代码检查，不代表已核验每位用户设备上的数据）：

- 存档位于各设备、浏览器及 origin 的 localStorage，没有服务器同步。
- 学生已有内部 ID，当前通过姓名卡片 + 4 位 PIN 进入；老师只有本机统一 PIN。
- 存档含进度、星星、选音、设置、已完成题目记录和前后测题组。
- 正常更新及项目清缓存脚本保留 localStorage；手动清网站数据、换设备或换 origin 则不能依赖原存档。
- `EVENT_LIMIT = 8000`，超限会裁掉最早记录；旧版 `migrateLegacyState()` 会重置 events、autoHistory、battery。
- 已有全学生 CSV 导出，以及单学生 JSON 导出／覆盖导入；没有全名册一键备份和恢复。

实施清单：

- [ ] 审计并修复旧版迁移，保留可恢复的逐题记录、题组与学习进度；迁移前可备份、失败可恢复。

- [ ] 登录账号与显示姓名分开，记录绑定不变的内部 ID；不能按中文姓名自动合并旧学生。
- [ ] 确定是否需要跨设备同步；若需要，再选择认证、数据库、离线同步与冲突处理方案。

## NT-002：iPad 首次启动音频不完整

用户报告：清缓存后第一次在 iPad 打开游戏，有的内容有声音、有的没有。
用户提出“点开始后，快速加载所需资源，再进入游戏”的方案，待验证。

已知情况与边界：琴声由 Web Audio 实时合成，没有琴声采样文件需要下载；念题使用系统语音。
不能直接把缺音归因于缓存仍在下载。此前 Mac 浏览器缓存流水线通过，不等于此 iPad 音频问题已解决。

实施清单：

- [ ] 在用户 iPad 上复现，并记录 iPadOS、浏览器／主屏幕模式、首次与再次打开的差异。
- [ ] 区分缺失的是琴声、中文语音、英文字母语音，还是多个通道。
- [ ] 检查首次用户手势、AudioContext 状态、resume 完成时机，以及切后台／锁屏后恢复。
- [ ] 检查语音列表就绪、voiceschanged、中英文声音选择及播放失败处理。
- [ ] 验证“点开始 → 初始化／解锁 → 检查就绪 → 进入”的方案；显示真实状态，不能只等固定秒数。
- [ ] 为初始化超时或失败提供明确提示、重试或用户可选择的继续方式，避免无限 loading。
- [ ] 实机验证清缓存首次启动、再次启动、离线、后台恢复、关闭声音等场景。

完成标准：iPad 实机复测通过，首题前必要音频状态可确认，失败可诊断和重试；
记录实测环境及结果后才能标记完成。
