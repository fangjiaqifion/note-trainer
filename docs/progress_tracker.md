## NT-001：账户身份与训练／测试数据长期保存

当前主要供用户自己的少量学生非商用使用，用户以中国内地为主、香港为辅。
优先采用免费、简单的本机保存和教师手动备份，保留未来扩展空间。远程页面
只是下载游戏：记录仍保存在使用它的设备、浏览器及 origin 上，不会自动送到老师处。
更新游戏时应保留已有数据；姓名不应作为身份匹配依据。独立远程登录尚未决定。
用户表示已获得伦理批准，机构没有指定存储地点；具体用途与处理方式仍须对照已批准方案。

已核查的现状（代码检查，不代表已核验每位用户设备上的数据）：

- 存档位于各设备、浏览器及 origin 的 localStorage，没有服务器同步。
- 学生已有内部 ID，当前通过姓名卡片 + 4 位 PIN 进入；老师只有本机统一 PIN。
- 存档含进度、星星、选音、设置、已完成题目记录和前后测题组。
- 正常更新及项目清缓存脚本保留 localStorage；手动清网站数据、换设备或换 origin 则不能依赖原存档。
- `EVENT_LIMIT = 8000`，超限会裁掉最早记录；旧版迁移曾重置 events、autoHistory、battery，现已修复。
- 已有全学生 CSV 导出，以及单学生 JSON 导出／覆盖导入；没有全名册一键备份和恢复。

实施清单：

## NT-003：远程同步与研究者数据管理（进行中）

用户已决定推进 Supabase 集成，要求简单、低负载、稳健，免费方案优先。目标是 GitHub
Pages 托管网页，练习先保存在设备，联网后可靠同步到 Supabase，教师能汇总和导出；
不能声称现有实验已经可用于真实学生，正式上线和推送仍遵循发布授权及流水线。

试验记录（2026-11-04）：应用户要求创建免费 Supabase 组织 `Note Trainer Research`，
及新加坡区域测试项目 `note-trainer-synthetic-test`。项目仅含虚构记录，尚未接入游戏。
在隔离 schema 中写入三条记录，并重复写入一条：按事件 ID 去重后仍为三条；
按学生汇总题数、首答正确率和平均反应时的结果符合预期。测试表启用 RLS，
SQL 权限检查显示 anon 和 authenticated 均无 schema 使用、表读取及插入权限。
这是管理员 SQL 编辑器的功能试验，不代表客户端授权、同步、备份或生产安全已通过。
内地与香港的数据库请求延迟、失败率尚未实测；Supabase MCP 尚未连接。
进一步隔离试验：在事务内创建临时测试表和 RLS 策略，模拟两个不同的 authenticated
身份及无身份请求，分别验证 A 只看到 A 的记录、B 只看到 B 的记录、无身份看不到记录；
尝试以 A 写入 B 的记录被拒绝。事务已回滚。此为数据库角色模拟，非真实登录或 API 测试；
教师归属、研究者权限、离线队列及跨设备冲突尚未实现或验证。
评估结论：Supabase 可继续作为候选，但免费版无自动备份、低活动可能暂停，默认认证邮件
每小时限额较低；在真实网络、恢复与迁移测试之前，不将其作为唯一数据副本或正式方案。
用户要求试用简单的 Supabase 架构。新增隔离的合成数据同步队列原型：
`experiments/supabase_sync/`。自动测试覆盖断网保留、响应丢失后重试、发送期间新记录、
不完整回执及本机写入失败；接收端仅为内存模拟，尚未接入 Supabase 或游戏。
本机网络访问项目健康检查得到 HTTP 401，耗时约 1.25 秒；仅证明该次请求到达需认证的
服务，不代表数据库读写速度，也不能代表内地或香港用户的网络。
用户确认后，测试项目已启用匿名登录。建立 `nt_sync_events` 和批量 RPC，RLS 按身份
隔离；SQL 事务中的模拟身份测试验证回执、重复提交去重、同 ID 不同内容拒绝和跨身份隔离。
本地传输原型增加会话保存、刷新失败不替换身份、批次最多 50 条；跨设备恢复或与游戏连接
尚未验证；匿名注册尚未配置防滥用验证，不可用于真实学生。
2026-11-04 用户提供公开客户端配置后，运行 `node experiments/supabase_sync/live_test.mjs`：
真实 API 匿名注册、虚构数据上传、模拟回执丢失后重试去重、第二身份无法读取第一身份记录均通过。
测试在该 Supabase 测试项目留下两个匿名身份及两条虚构记录；未访问真实学生数据。
这仅验证本机一次端到端流程，未验证内地／香港网络、真实设备、跨设备恢复或游戏集成。
