## 0. Main conclusion

The observed layout fix existed locally but was not deployed. Local main was three commits
ahead of origin/main; Pages still used `.stage{flex:1;min-height:0;...}`, pushing the keyboard
to the bottom. Local code used `flex:0 0 auto`. After the authorized push, remote inspection
confirmed it. The configuration/layering was understandable, but the nearly 5,900-line file,
lack of automated regression, and repeated documentation/count drift were maintenance risks.

## 6. Second regression audit: D/E clef collapses to D

Historical reproduction baseline `dc501ef`, after a prior name-spacing fix. With D4/E4
fully learned and selected, ten generated clef sessions each contained eight D4s.
window.__dbg.buildQuestions(3) reproduced it. This was a selection-code bug, not caching.

| ID | Priority | Cause |
|---|---|---|
| C1 | P0 | Fixed pool B3/C4/C4B/D4 intersected with D/E to leave D only |
| C2 | P1 | Fallback ran only for empty pool, not a one-item collapse |
| C3 | P1 | Tests only used default all-learned selection; clefOrderCheck missed D/E |
| C4 | P2 | spreadLetters heuristic could reorder but not expand a collapsed pool |
| C5 | P2 | spaceOut silently returned original order on failure; tests missed collapsed coverage |
| C6 | P2 | Ledger refill sampled already-used clef/positions |
| C7 | P2 | Manual cache IDs and visual deployment checks amplified stale-page confusion |

At this intermediate stage clef switched to activeNotes(pos), added C4B for checked C4,
and inserted the nearest learned opposite-clef note for same-clef pools, preferring a real
bass note over C4B. Counts balanced by name, C spellings alternated, spreadLetters/CLEF_POOL
were removed, and a backtracking spaceOut was shared. Ledger refill excluded used positions.

Intermediate tests checked D+E, E, B, C, D+E+A3, all; thirty repeats across seven named
skills/daily, and 100 ledger generations. D/E then produced mixtures including B3, such as
B3,D4,E4,D4,E4,B3,D4,B3. The tests passed but this still violated strict target selection.
[The follow-up audit](docs/audit_20261104_followup/audit.md) later removed unchecked targets
and strengthened the full selection matrix. Do not reintroduce that intermediate opposite-clef rule.

Other intermediate boundaries: single-target contrast/distractor questions needed alternatives;
skills 6–8 used abstract positions and skill 9 selected registered pairs. The original audit's
claim that all skills 6–9 ignored selection was imprecise and is corrected by this distinction.

## 7. Historical release mechanism, superseded

The initial release implementation ran tests (with a skip flag then documented), hashed
index/manifest/icons, wrote build/cache IDs, used a Python server on 8765, opened reset pages
in Safari/Chrome, and polled a remote build tag up to 180 seconds. It described browser
automation permissions and a warning after timeout.

Those procedures are preserved here as history, not operational guidance. Later audits
replaced them with a fingerprinted no-store Node server, hashes for every release file,
strict timeout failure, atomic locks, and actual one-time loopback load receipts across
Safari/Chrome and both local hostnames plus remote. Full runtime delivery must not skip
required tests, rely on a fixed wait, manually bump caches, or treat a push as verified load.
Game-scoped reset always preserves learner localStorage and unrelated caches.
